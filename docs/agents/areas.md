# Coordinator area notes

Detailed rules and lessons for each part of the project, kept out of AGENTS.md so that file stays short. Read the section of the area you change before you change it; AGENTS.md applies to every task. Keep this file current like AGENTS.md: a change that alters a rule here updates it in the same PR.

## Solution views

- Files: `.solution.json` (manifest), `docs/solution-order.md` (owner's order), `docs/SOLUTION-OVERVIEW.md` (generated by `tools/solution-overview.mjs`, project tool), `docs/SOLUTION-DASHBOARD.md` (generated by `tools/solution.mjs`, copied from the template).
- Refresh: `npm run solution:refresh` reads every component's `main` from GitHub at one resolved commit each (set `GH_TOKEN` in the environment if the API rate limit is reached; never commit it). Commit both files together; the PR names the snapshot time.
- Check: `npm run check:order` validates the order offline (CI runs it); `npm run check:solution` validates the manifest, sources and links through GitHub.
- Gap review: the overview's last section; procedure in [gap review](gap-review.md). Its heuristics live in `gapReview()` in `tools/solution-overview.mjs`; a false positive is fixed there, not by editing the generated page.
- `tools/solution-overview.mjs` reads two backlog layouts: the generated ledger (Status, Priority, Effort, Remaining, Depends on, Unlocks, Agent, Procedures, Decisions, and a "Feature steps"/"Steps" table) and the authored four-column summary (Signal, Priority, Status, Effort, with "Human action required"). A component on another layout shows no records; check the source table in the overview after a component's harness release changes its ledger.
- State rules in the overview: Ready = an agent can start now (record Agent cell 🤖, or an authored record with no human action); Waiting = ⏳ or open prerequisites; Owner = a 🧑‍🔧 procedure or 🤔 decision with no agent work left; Blocked = status Blocked.

## Cross-repository backlog

- Files: `docs/BACKLOG.md`, `docs/SOLUTION.md`.
- A record here owns a contract, a compatibility decision, an end-to-end acceptance or a coordination step. Its `Components` row links the component records it depends on; their implementation, next actions and closure stay in their own backlogs.
- A component record closes on its own criteria; never hold it open for integration here.
